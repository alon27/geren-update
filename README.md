**五菱车控**是一款面向 Android 16（API 36）的五菱车联网客户端，独立包名 `com.wuling.app.repack`，基于官方接口重新实现，**无需安装官方 App 即可单独使用**。它适合官方 App 出现兼容性故障、或你想要更顺手的车控与能耗统计时使用。无广告，登录凭据经系统级加密后仅保存在本机。

## 功能特性

### 车控与提醒

- **车辆状态**：续航、电量、油量、车门/车窗/后备箱状态实时查看
- **车辆控制**：远程上锁/解锁、车窗、寻车、空调；解锁/开窗/启动等敏感操作二次确认
- **离车提醒**：车窗未关/车门未锁/后备箱未关 → 通知可一键锁车、关窗
- **充电提醒**：开始充电 / 已充满 / 充电中断 / 电量偏低（阈值可调）
- **蓝牙数字钥匙**：BLE 无感连接、靠近自动解锁

### 位置、能耗与充电

- **位置服务**：车辆定位与停车记录，逆地理解析中文地址，显示当地天气
- **能耗统计**：日/月/年三维度能耗，趋势图 + 能量构成饼图
- **充电功率显示**：充电时实时显示充电功率（kW），首页电量卡、详情页「电池与充电」、桌面小组件三处同步展示；未充电时不显示
- **循环预约充电**：详情页查询、设置、修改、取消循环预约充电时段与充电上限（依赖车端接口，部分车型可能不支持）

### 桌面、更新与安全

- **桌面小组件**：2×3 车辆状态卡片（独立联网刷新）+ 4×1 快捷控制条（锁车/关窗/寻车）
- **自动更新**：启动检测新版本，15 个 GitHub 加速源自动测速择优、失败回退、MD5 校验
- **登录态持久化**：登录凭据经 AndroidKeyStore 硬件级加密存储，Token 失效或被顶号时自动静默重登，退出重进、杀进程均不掉线
- **调试日志**：API 报文（脱敏）落盘持久化，可筛选、搜索、导出

## 自动更新

App 启动时自动检查更新（也可在「我的 → 检查更新」手动触发）。本仓库是**唯一权威源**；[Gitee 仓库](https://gitee.com/daiyuxiang520/geren-update) 为其国内镜像，两份 [`update.json`](./update.json) **内容完全一致**（含一致版本号与同一 APK 下载地址），因此镜像同步不会造成分发分歧：

| 读取源 | 地址 | 说明 |
|---|---|---|
| Gitee（镜像） | `https://gitee.com/daiyuxiang520/geren-update/raw/master/update.json` | 国内直连，无需代理 |
| GitHub（权威） | [`update.json`](./update.json)（经公益加速源） | 兜底，取到的是同一份内容 |

- **检查更新**：并发请求全部源，取版本号最大者；**版本相同时保留先返回者**，国内 Gitee 通常几十毫秒就返回，自然胜出；海外则是 GitHub 加速源先到
- **下载**：两份清单的 `apkUrl` **统一指向 Gitee 发行版附件**，无论从哪个源检到更新，最终都从 Gitee 直连下载（不经第三方公益代理）；下载时自动测速择优（上次最快源优先，失败自动回退）→ MD5 校验 → 调起安装器，全部失败自动回退浏览器下载
- **降级保障**：Gitee 不可用时仍能从 GitHub 加速源读到版本信息；若需手动下载，GitHub Releases 与 Gitee 发行版各存有一份完整 APK
- 更新弹窗内可**手动选择下载源**（仅本次生效），每个源实时显示延迟

GitHub 加速源列表提取自 [XIU2/UserScript](https://github.com/XIU2/UserScript)「Github 增强 - 高速下载」，经本地实测筛选。

## 构建

仓库不含任何密钥，敏感配置通过 `local.properties` 或环境变量注入。

```bash
# 1. 凭据配置
cp local.properties.example local.properties   # 按注释填写（缺失部分功能不可用，但可正常构建）

# 2. 签名（可选，未设置时 release 回退 debug 签名）
export WULING_KEYSTORE_PATH=/path/to/your.keystore
export WULING_KEYSTORE_PASSWORD=your_store_password
export WULING_KEY_ALIAS=your_key_alias
export WULING_KEY_PASSWORD=your_key_password

# 3. 构建（需 JDK 17 + Android SDK 36）
./gradlew assembleRelease                       # 产物在 app/build/outputs/apk/release/
./build-android16.sh                            # 或使用预置 Docker 镜像构建
```

| **v145** (4.9.1) | **紧急修复：v144 的反馈提交 100% 失败**。① **症状**：v144 首发真机实测，点「发送反馈」必定弹「提交失败」，内容为 Web3Forms 返回的英文原文 `This method is not allowed. Use our API in client side or contact support with server IP address (Pro plan is required)`。② **根因**：**OkHttp 默认不发送 `User-Agent`**，而 Web3Forms 免费版依据 UA 判断请求是否来自浏览器，非浏览器一律 403 拒收。逐一实测确认（**唯一决定放行的是 UA**）：仅 Content-Type → 403；**+ 浏览器 UA → 200**；`+ Origin` → 403；`+ Referer` → 403；三者同加 → 200。错误文案里的 `server IP address` **具有强误导性** —— 与 IP 无关，手机/电脑/任何网络同样失败，这也是首发时误判为「数据中心 IP 限制」的直接原因。③ **修复**：OkHttp 请求显式加 `User-Agent`（伪装移动端浏览器）。该常量设为 **`internal`**（非 private）并在单测中断言「含 Mozilla 特征、不含 Wuling 字样」，防止后来者出于「更诚实」把它改成 App 自己的 UA 而导致功能**静默失效**。④ **顺带修掉一个体验缺陷**：错误弹窗此前会**直接把服务端英文原文展示给用户**——那文案是写给开发者的，用户既看不懂也不知下一步做什么。现 403 与含 `not allowed` 的响应统一转为「反馈通道暂时不可用，请改用邮件反馈」，兜底分支也不再回显任何服务端英文。⑤ 新增 3 个单测守卫（总数 220 → **223**）。⑥ **vc=145 而 versionName 仍为 4.9.1**：这是同一功能的当日修复，非新功能发布，故只递增 versionCode（但**必须递增**，否则已装 v144 的用户检测不到更新） |
